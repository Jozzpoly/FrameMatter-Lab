# FrameMatter Lab — agent operating contract

This repository is an active research program, not a feature backlog.

## Start here

For current work, read in this order:

1. `docs/convergence/CURRENT.md`
2. `docs/convergence/VISION.md`
3. `docs/convergence/ROADMAP.md`
4. only then follow links into historical P1/Q0/evidence documents as needed.

Historical roadmaps and readiness systems remain evidence/provenance. They do not override the current Convergence control plane.

## Meaning of “continue”

When the Owner says `continue`, `kontynuuj`, `dalej` or equivalent:

1. recover the current research objective and the reason it matters;
2. reacquire live repository truth when branch/HEAD/CI/runtime state matters;
3. read `docs/convergence/CURRENT.md` and distrust it if live evidence contradicts it;
4. choose the smallest next action with the highest decision-relevant information;
5. execute reversible already-authorized repository work autonomously;
6. validate the actual claim at the fidelity it requires;
7. update `CURRENT.md` when the project boundary materially changes;
8. stop only at a real evidence boundary, Owner-judgement boundary, or material blocker.

Do not return a menu merely because one local task ended.

## Research discipline

- Evidence outranks roadmap sequence.
- Owner play is the oracle for feel, legibility, desire, building instinct and other genuinely experiential questions.
- Automation must close technical uncertainty before spending Owner attention.
- Exact release artifacts matter whenever debug/editor behavior could diverge from shipped behavior.
- A mechanism is not a product concept merely because it exists in code.
- Prefer small falsifiers over premature frameworks.
- Preserve historical evidence; do not rewrite old failures into success.
- Do not generalize class names, current provider layout, `Space`, joints or the current grid into final ontology without pressure.
- Do not expand into performance, governance, representation, mechanics catalogues or tooling merely because they are interesting.
- If a simpler authored fake/control gives the needed gameplay evidence, it may beat a generalized mechanism until repeated pressure earns the generalization.

## Current product pressure

The active near-term loop is:

> ordinary editable Matter world → direct dig/build → Matter can acquire physical autonomy as a consequence → ride/interact → keep editing while moving → introduce one local material/structural law → observe understandable causal history.

The goal is not “more physics features.” The goal is a world whose material organization can be understood and changed through play.

## Protected distinctions

Treat these as defended until stronger evidence says otherwise:

- Matter identity != storage coordinate != provider/body/collider identity
- logical Space != provider != simulation domain
- adjacency != rigid connectivity
- contact != support != mechanical constraint != rigid bind
- storage rebase != Matter mutation
- provider transition != topology split != reintegration/bake
- representation != world truth
- automated PASS != Owner experiential PASS
