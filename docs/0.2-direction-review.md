# 0.2 research direction checkpoint

Status: direction review after the first topology/mechanics expansion. This is not a final architecture plan.

## Original contract still governs

FrameMatter Lab exists to test the smallest editable-world substrate in which local Matter may change representation, become a dynamic construct, and remain editable without logical identity collapsing into render/physics object identity.

The repository must therefore optimize for information value and falsifiability, not for accumulating game features or mechanically extending a successful test family.

## Live truth at this checkpoint

Defended in bounded CI evidence:

- Matter remains authoritative across render/collision rebuilds.
- The same local Matter model can back static and dynamic representations.
- Moving constructs can mutate while rebuilding mass properties.
- Explicit support-frame semantics can carry an actor on free rigid constructs without scene parenting or uncontrolled actor->construct force exchange.
- Topology split/merge can preserve retained Matter world-space and instantaneous velocity-field continuity.
- Retained Matter lineage can survive address/frame/body replacement while destroyed/recreated Matter receives new logical identity.
- Explicit rigid binding can distinguish compatible reframing from inelastic bind policy.
- Mechanical constraints may couple independent frames without collapsing them.
- Constraint ownership can follow retained Matter through topology replacement.
- Constraint graphs can partition on split and contract on merge; relations that become internal/self edges can retire.
- Hinge succession can preserve a full oriented constraint frame.
- Motor and angular-limit behavior can survive endpoint succession.
- One split can partition two independently stateful hinges onto different successors while preserving distinct owner, frame, identity and active behavior.

These are bounded semantics, not evidence for a production world/mechanics architecture.

## Critical finding: evidence has outrun the reusable substrate

The current runtime/core remains intentionally small while many increasingly large probes manually reconstruct topology transactions, successor selection, frame mapping, lineage movement, joint rebasing and lifecycle ordering.

At this checkpoint the repository contains roughly 36 test scripts (~366 KB) versus 12 runtime/lab scripts (~29 KB). A test-heavy research lab is acceptable, but another long series of copy-expanded graph probes would increasingly validate test-local orchestration rather than a shared substrate.

The current `lab/main.gd` is also still essentially the original G0 interactive scene. The demonstrated semantics have not yet been recomposed into a current end-to-end interactive lifecycle.

## Decision: end the current mechanics expansion deliberately

One final bounded challenger remains justified:

**Stateful graph contraction capstone**

`External L -- stateful hinge -- A -- internal relation -- B -- stateful hinge -- External R`

Then explicit rigid bind `A + B -> merged successor`.

Required result:

- both external stateful hinges converge onto the merged successor,
- each preserves its distinct owner lineage, full logical constraint frame, joint identity, motor configuration and angular limit behavior,
- the A<->B relation retires when it becomes internal to one rigid successor,
- momentum/energy semantics remain those already defended for the bounded inelastic rigid merge.

Whether this PASSes or FAILs, it is the stop condition for the current standalone mechanics-probe expansion. Serial chains, loops, breakable links and richer machinery are deferred until a real integrated consumer makes one necessary.

## Next campaign: integration before generalization

Do not first design a universal topology transaction framework from the probes. That risks fossilizing test assumptions.

Instead create the smallest reusable execution pieces demanded by a new integrated consumer.

### Integration target A — World <-> Construct representation lifecycle

Prove that one authoritative Matter volume and retained lineage can move through a real lifecycle:

1. editable static-world representation,
2. activation into a dynamic ConstructBody without changing logical Matter identity,
3. physical translation/rotation,
4. live Matter editing while dynamic,
5. deactivation/reframing back into a static representation while preserving intended world-space Matter and logical continuity.

This is closer to the project's founding question than another larger joint graph. It should expose which transaction concepts genuinely deserve reusable code.

### Integration target B — actor continuity through activation/deactivation

Once A is mechanically sound, place the bounded frame-aware actor on the same Matter region and challenge support continuity while the region changes representation class. This should reuse the explicit handoff lessons from topology replacement rather than relying on one-tick contact reacquisition.

### Integration target C — topology change inside the integrated lifecycle

Only after A/B, mutate the moving construct so it splits. Successor mapping, lineage, actor support and any deliberately included mechanical relation must be processed through the shared execution path created by the integrated consumer, not reimplemented inside a giant standalone probe.

This is the first serious test of whether the accumulated evidence composes.

## Representation debt: important, but do not let it block the small integration slice

Box-per-cell collision is already falsified as a scalable dynamic representation. Godot/Jolt also gives no free dynamic-trimesh escape hatch: concave/trimesh collision is intended for static level geometry, while dynamic concave bodies require convex decomposition/compound convex representation and shape count itself has performance cost.

Therefore a dedicated representation campaign is necessary after the small lifecycle integration establishes the correct semantic consumer. Candidate research should compare fewer merged primitives, convex decomposition/convex clusters and other bounded approximations against the existing box-per-cell truth representation.

Do not optimize rendering/collision before the lifecycle consumer tells us what update granularity and topology behavior the representation actually needs.

## Deliberately deferred

Not next unless new evidence forces them:

- longer hinge chains merely to increase graph size,
- closed mechanical loops and overconstraint,
- breakable-link gameplay policy,
- Create-like content/mechanism catalogues,
- production persistence/network IDs,
- streaming/procedural terrain,
- nested moving frames,
- portals/spatial links,
- Planet Matter,
- JV-grade vehicle systems,
- large-world coordinates.

Large-world coordinates in particular should not be enabled preemptively; Godot documents explicit performance/memory costs and recommends them only when actual scale requires them.

## Current working hypothesis

The useful emerging boundary is not "a voxel vehicle system" or "a joint graph engine". It is a topology-aware editable-Matter substrate in which several dependent domains can survive representation replacement through explicit mappings:

- retained Matter identity,
- spatial/local-coordinate mapping,
- physical state/momentum policy,
- actor support ownership,
- mechanical relation ownership and state,
- host runtime lifecycle ordering.

The next phase must determine whether those mappings can become a small coherent transaction/execution model through a real World <-> Construct consumer. If they cannot, the current semantics must be revised rather than hidden behind a larger abstraction.
