# 0.2b critical course correction

Status: fresh audit of the 0.2 direction checkpoint. This supersedes only its ordering/terminology where stated; it does not erase prior evidence.

## Why this correction exists

The previous direction review correctly identified that standalone mechanics probes were reaching diminishing returns and that the next phase should be driven by an integrated consumer.

A second audit exposed a deeper ambiguity in the proposed `World -> Construct -> World` milestone: returning an arbitrarily rotated local voxel lattice to a canonical world lattice is not necessarily a representation change. It may be a topology/material conversion requiring quantization or resampling.

The next campaign must therefore separate representation lifecycle from world-lattice reintegration before implementation begins.

## Fresh live-state reading

The current repository has a strong bounded evidence ratchet but a deliberately tiny reusable runtime:

- 6 `matter/` scripts,
- 2 `construct/` scripts,
- 3 `actor/` scripts,
- 2 `lab/` scripts,
- roughly three dozen increasingly large research tests.

The interactive lab is still essentially the original G0 static Matter demo. Most topology, lineage, support-frame and mechanical-graph semantics currently exist as repeated orchestration inside probes rather than as one reusable execution path.

This was appropriate for falsification. Continuing the same pattern for many more graph cases would increasingly test probe-local code rather than the substrate.

## Critical semantic correction: three operations were being conflated

### 1. Representation transition / freeze

One logical local Matter Space keeps the same local lattice and Matter identities while its host representation changes:

`static local representation <-> dynamic rigid representation`

A dynamic Space may later become static at an arbitrary world transform. It does **not** need to snap to a global lattice. This can remain lossless at the cell/lineage level.

### 2. Lossless lattice reintegration

A local Matter Space is absorbed into a larger canonical lattice only when the relative transform maps cells exactly onto cells.

For the current unit cubic lattice this implies a discrete lattice-compatible transform: integer cell translation plus an orientation that maps lattice axes onto lattice axes. This is a different operation from merely freezing a Space.

### 3. Bake / resample

An arbitrarily rotated or otherwise incompatible local Matter Space is converted into a canonical target lattice by resampling/voxelization.

This can create, destroy, merge or split target cells. It therefore cannot automatically promise 1:1 Matter lineage continuity. It needs an explicit conversion/provenance policy and should not be hidden behind the word `deactivate` or `return to world`.

Current rule: **do not build bake/resample into the first integrated lifecycle.**

## Donor evidence reinforces this separation

Create-style moving contraptions are useful donor evidence precisely because assembly/disassembly has to reason about orientation and state restoration rather than treating arbitrary motion as a trivial reversible transform. Its current mechanical-bearing implementation conditionally disassembles around a returned/near-initial orientation for one movement mode, and historical/current issues show orientation/state bugs across assemble/disassemble boundaries.

Valkyrien Skies remains useful as evidence for the opposite strategy: maintain a distinct ship/local coordinate space and explicit world<->ship transforms rather than constantly baking a moving structure back into the canonical world representation. Current VS APIs and bug reports continue to expose the complexity of ship-space/world-space transforms, loading and joint/ship lifecycle.

These are donors/negative knowledge, not architectures to copy.

## Mechanics campaign stop condition remains, but its role is narrower

One final standalone mechanics challenger is still justified because it closes a clean missing inverse in the existing evidence:

### M-CAP — stateful graph contraction

`External L -- stateful hinge -- A -- internal relation -- B -- stateful hinge -- External R`

Explicit rigid bind: `A + B -> merged successor`.

Required bounded evidence:

- both external hinges converge onto the merged successor,
- each retains its own Matter owner lineage,
- each retains its own full oriented constraint frame and logical edge identity,
- each retains distinct motor and angular-limit behavior,
- the A<->B edge retires when it becomes internal/self relation,
- merge momentum/energy behavior remains consistent with the already defended inelastic-bind contract.

PASS or FAIL ends the standalone mechanics expansion. Do not continue directly into longer chains, loops, breakable-link policy or mechanism catalogues.

## New campaign: integrated local-Space lifecycle

The first consumer must be smaller and more precise than `World -> Construct -> World`.

### I0 — persistent logical Space identity

Introduce only the minimum logical carrier required by the consumer. Working concept, not canonical naming/API:

`MatterSpace = CellVolume + Matter lineage + stable logical-space identity/revision`

The purpose is not to design a universal world object. It is to give static and dynamic representations one logical object that survives host-node/body replacement.

Falsification condition: if the lifecycle still needs to duplicate/copy logical Matter in ways that make authority ambiguous, the abstraction is wrong.

Do not put rendering, physics-body IDs, actor state or joint nodes into MatterSpace.

### I1 — Static Local Space -> Dynamic Local Space -> Static Local Space

First real integrated lifecycle:

1. one authoritative MatterSpace is represented statically,
2. activation replaces only the representation with a `ConstructBody`,
3. the dynamic representation translates and rotates freely,
4. Matter is edited while moving,
5. the same logical Space freezes back to a static representation **at its current arbitrary frame transform**,
6. the post-freeze representation remains editable.

Required evidence:

- one logical Matter/lineage authority before, during and after transition,
- no material or lineage mismatch for retained Matter,
- no representation double-ownership during commit,
- activation has no world-space Matter jump,
- dynamic live edits survive the later freeze,
- freeze preserves current world-space cell centers within numerical tolerance,
- arbitrary orientation is preserved rather than snapped to canonical world axes,
- replacement commits at the already defended pre-PhysicsServer-step boundary when physics-body identity changes.

This deliberately tests representation lifecycle, not world-grid reintegration.

### I2 — actor continuity through representation-class transition

Place the existing bounded frame-aware actor on the same Space.

Challenge:

`static support -> dynamic support -> static support`

Required evidence:

- no one-frame contact-reacquisition slip,
- explicit support mapping/hand-off when representation identity changes,
- no teleport,
- grounded state preserved where geometrically valid,
- support velocity changes coherently when dynamic motion starts/stops,
- no uncontrolled actor->construct impulse is reintroduced.

Do not broaden this gate into a production capsule controller.

### I3 — topology mutation through the shared lifecycle path

Only after I1/I2 pass, split the moving MatterSpace by editing Matter.

The purpose is not another split probe. The purpose is to force the integrated execution path to reuse defended semantics for:

- successor selection,
- compact local-coordinate mapping,
- retained lineage,
- physical state/velocity-field inheritance,
- actor support succession,
- one deliberately chosen mechanical relation if useful.

Success condition: these are no longer manually reimplemented inside one giant test script.

## Then, and only then, test actual world-lattice transfer

### W0 — aligned extraction and reintegration

Introduce a minimal canonical static world lattice only after the local-Space lifecycle is coherent.

Bound the first case to lattice-compatible transforms.

Test:

`world cells -> independent MatterSpace -> dynamic motion -> lattice-compatible pose -> reintegrate into world`

Required evidence:

- no duplicated Matter authority,
- extraction leaves the source world cells unowned/empty as defined by the experiment,
- retained lineage transfers rather than cloning,
- exact cell-to-cell mapping on reintegration,
- collisions with occupied destination cells are explicit transaction failures/policies, not silent overwrite,
- external dependencies crossing the extraction boundary are either rejected or explicitly transferred; no heuristic dangling references.

### W1 — incompatible orientation

Do **not** call this ordinary reintegration.

First decide whether the product even needs arbitrary `bake-to-grid`. If it does, design it later as an explicit conversion operation with measurable geometry/material/provenance error. Same-cell identity preservation should not be assumed.

## Reusable execution model: extract from the consumer, do not predesign it

The accumulated evidence strongly suggests recurring transaction concepts, but implementation should be extracted only when I1-I3 need them.

Likely minimum concepts to watch for:

- persistent logical MatterSpace,
- old-frame -> new-frame local transform/mapping,
- representation replacement commit at pre-step boundary,
- retained/destroyed Matter identity mapping,
- dependent handoffs (actor/mechanical edge) keyed by explicit ownership,
- physical-state policy for dynamic successors.

Do not create a universal `TopologyTransaction` framework on day one. First let duplicated logic appear inside the integrated consumer, then extract the smallest stable common path.

## Representation campaign moves up, but not before I1

The box-per-cell dynamic collision representation is already falsified as scalable. Godot/Jolt offers primitive and convex compound options for dynamic bodies; concave/trimesh collision is fundamentally aimed at static geometry, while many convex shapes also become expensive.

After I1 establishes actual lifecycle/update requirements, run a dedicated representation campaign. Compare candidates against the existing box-per-cell truth representation.

Research questions:

- How few primitive boxes can greedy 3D merging produce for typical Matter regions?
- What edit-locality does merged-box rebuilding permit?
- When does convex decomposition outperform merged primitives, and what geometry error does it introduce?
- Can collision representation update only dirty regions while logical Matter remains whole?
- What representation is appropriate for near/interactive versus far/frozen constructs without turning representation levels into hard gameplay modes?

Do not optimize the visual mesher and collision representation as one problem unless evidence says they share the same optimal partitioning.

## Other major debts, reprioritized

### High after integration

- scalable dynamic collision representation,
- volumetric/query-based actor controller with walls/slopes/steps/ceilings,
- finite physical actor->construct force exchange,
- persistence semantics for logical Space/Matter lineage once identity must cross save/load.

### High only when a consumer appears

- multiple simulation domains / migration,
- nested moving frames,
- portals/spatial links/query routing,
- large-world coordinates,
- curved/Planet Matter providers.

### Deliberately not next

- bigger joint graphs for their own sake,
- Create-like content catalogue,
- JV-grade vehicle subsystem,
- networking/multiplayer,
- procedural biomes/crafting/survival,
- arbitrary bake-to-world-grid.

## New execution order

1. **M-CAP:** one final stateful graph-contraction challenger; stop standalone mechanics expansion.
2. **I0/I1:** minimal logical Space carrier plus Static Local <-> Dynamic Local lifecycle.
3. **I2:** actor continuity through representation transition.
4. **I3:** one topology split through the shared integrated execution path.
5. **R0:** scalable dynamic representation campaign informed by the real consumer.
6. **W0:** aligned canonical-world extraction/reintegration.
7. Re-audit before choosing between volumetric actor work, richer mechanics, streaming/world scale, nested spaces or spatial links.

This order is intentionally reversible. A material FAIL can reorder or invalidate later gates.

## Current north-star test

The near-term question is no longer:

> Can another increasingly complex joint graph survive a hand-written topology probe?

It is:

> Can one authoritative editable local Space survive real representation changes, physical motion, live editing and dependent handoffs through one small reusable execution path without collapsing Matter identity into engine objects?

If the answer is no, that is the next important failure to understand.
